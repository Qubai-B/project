# Perception-layer data minimization for screenshot-driven agents

**Supervisor progress report: [`POF.md`](POF.md)** · **Full write-up: [`PROJECT_RECORD.md`](PROJECT_RECORD.md)** (decisions, methodology, results, conclusion) · numeric summary: `results/REPORT.md`.

Proof of concept for a visual redaction guard that masks PII in screenshots
before they reach a vision-language model, evaluated on mock Nigerian government e-service forms (tax self-assessment, driver's licence renewal,
international passport application).

## Layout and the HTML ↔ screenshot mapping

The rule everywhere: **one sample = one folder**, and everything about that
sample (the rendered HTML, the screenshot taken of it, the PII boxes found in it)
lives in that folder under fixed file names. Nothing is matched by naming
convention across folders; if you can see the `.png`, the `.html` that produced
it is next to it.

```
<repo root>/
├── forms/                          # SOURCE: mock portal templates (hand-written)
│   └── <form_id>/
│       ├── index.html              # Jinja2 template, {{ v.<field> }} placeholders
│       ├── styles.css
│       └── form.json               # field manifest: selector, PII type, which tasks need it
│
├── data/
│   ├── identities/
│   │   └── identities.jsonl        # 50 synthetic Nigerian identities (see schemas/pii_formats.md), id = I0001…
│   │
│   ├── benchmark/                  # GENERATED by scripts/render_benchmark.py
│   │   ├── manifest.jsonl          # index: one line per sample folder below
│   │   └── <form_id>/<identity_id>/<fill_state>/
│   │       ├── page.html           # the exact HTML that was screenshotted
│   │       ├── screenshot.png      # 1280×(auto) full-page capture of page.html
│   │       └── annotations.json    # ground-truth PII boxes read from the DOM
│   │
│   └── trajectories/               # GENERATED by scripts/record_trajectories.py
│       └── <task_id>/
│           ├── task.json           # form, identity, goal, fields the task needs
│           └── steps/<step_no>/
│               ├── page.html       # DOM state *before* the gold action
│               ├── screenshot.png  # what the model is shown at this step
│               ├── annotations.json
│               └── action.json     # the gold next action
│
├── guard/                          # the redaction package (ocr → detect → policy → mask)
├── scripts/                        # pipeline entry points, numbered in run order
├── schemas/                        # JSON examples documenting every generated file
│
├── results/                        # GENERATED by eval scripts
│   ├── redacted/                   # mirrors data/ paths exactly, adds <condition>.png
│   │   ├── benchmark/<form_id>/<identity_id>/<fill_state>/{full,task_aware}.png
│   │   └── trajectories/<task_id>/steps/<step_no>/{full,task_aware}.png
│   ├── tables/                     # detection.csv, leakage.csv, step_accuracy.csv
│   └── figures/                    # privacy_vs_utility.png
│
└── demo/                           # recording of an off-the-shelf agent with the guard on
```

`results/redacted/` mirrors `data/` path-for-path, so for any screenshot the raw
image, its HTML, its ground truth and every redacted variant are reachable from
one path stem:

```
data/benchmark/tax_self_assessment/I0007/filled/screenshot.png
results/redacted/benchmark/tax_self_assessment/I0007/filled/full.png
results/redacted/benchmark/tax_self_assessment/I0007/filled/task_aware.png
```

## Pipeline

```
scripts/01_gen_identities.py      → data/identities/identities.jsonl           50 identities
scripts/02_render_benchmark.py    → data/benchmark/**                           3 forms × 50 × 3 states = 450 samples
scripts/03_record_trajectories.py → data/trajectories/**                        5 tasks × 3 identities = 15 trajectories, 51 steps
scripts/04_run_guard.py           → results/redacted/**                         full.png + task_aware.png + guard.json per screenshot
scripts/04_run_guard.py --detector presidio …  → guard.presidio.json            generic-detector baseline
scripts/05_eval_detection.py      → results/tables/detection.csv                Exp. 1  (no API needed)
scripts/06_eval_leakage.py        → results/tables/leakage.csv                  Exp. 2  (VLM, ~180 calls, cached)
scripts/07_eval_step_accuracy.py  → results/tables/step_accuracy.csv            Exp. 3  (VLM, ~153 calls, cached)
scripts/08_plot.py                → results/figures/
demo/side_by_side.py              → demo/<trajectory>.gif                       browser view | model input, per step
```

`./run_all.sh` runs everything in order (VLM stages are skipped without a key). Every stage is
re-runnable; VLM replies are cached in `results/cache/` keyed on model + image + prompt.

## The guard

```python
from guard import redact
img, detections, masked, timings = redact(screenshot, mode="task_aware", needs={"lga", "state"})
```

`guard/ocr.py` runs Tesseract (2× upscale) and groups words into *runs* split on large horizontal
gaps, so a form row becomes a label run and a value run. `guard/detect.py` classifies runs: in
**hybrid** mode a run whose left neighbour reads as a field label inherits that field's PII type
(this is what disambiguates NIN from BVN, both 11 digits); pattern rules and Presidio catch the rest.
**presidio** mode is the generic baseline. `guard/policy.py` keeps task-needed fields visible in
`task_aware` mode. `guard/mask.py` paints the boxes.

Integration point for an agent: call `redact()` on every screenshot before it is sent to the model.
That single insertion is the Paperasse middleware.

**Design notes from development.** (1) Screenshots taken right after an agent types carry the
browser's blue focus ring on that input, and Tesseract's layout analysis then skipped the text inside
it — i.e. the one value the agent had just entered went unmasked (9 of 2,895 values in the first full
run, every one of them the focused field). The guard now paints focus-ring-blue pixels white before
OCR (`neutralise_focus_ring`), uses full-layout mode (`--psm 3`) and drops bar-only tokens that
input borders produce. Binarising the image was tried and rejected: it removed borders but pushed
real values below any confidence cutoff. (2) The guard keeps words at any OCR confidence: an
uncertain word is still painted over, because a missed value is a privacy failure while an extra
box is only a utility cost.

## Experiments

| # | question | script | metric |
|---|----------|--------|--------|
| 1 | Does the guard find the PII? | 05 | precision / recall / F1 per type at IoU ≥ 0.5; type accuracy; mask coverage of GT text |
| 2 | Can the model still read it? | 06 | % of ground-truth values a VLM transcribes from raw / full / task-aware images |
| 3 | Can the agent still act? | 07 | step accuracy: correct next action from the screenshot, per condition |

Experiment 3 is offline: the model predicts one step at a time on recorded gold trajectories
(as in Mind2Web-style evaluation), so no autonomous agent is needed.

## Setup (replicates the exact environment on any machine)

```
git clone https://github.com/Qubai-B/project.git && cd project
./setup.sh                      # creates .venv from requirements.lock, downloads the spaCy model and Chromium
source .venv/bin/activate
```

Requirements: Python 3.9+ and Tesseract on PATH (`brew install tesseract` / `apt install tesseract-ocr`).
`setup.sh` checks both before doing anything.

| file                | purpose                                                        |
|---------------------|----------------------------------------------------------------|
| `requirements.txt`  | direct dependencies, loose ranges — edit this to add a package |
| `requirements.lock` | every package pinned (`pip freeze`) — what `setup.sh` installs |
| `.python-version`   | interpreter version the lock was produced with                 |

After adding a dependency: `pip install <pkg>`, add it to `requirements.txt`, then
`pip freeze | grep -v en-core-web-lg > requirements.lock`.

`.venv/` is git-ignored on purpose: a venv embeds absolute paths and platform binaries, so it is
rebuilt per machine from the lock file rather than copied.

Model/API keys go in `.env` (git-ignored); see `.env.example`.
